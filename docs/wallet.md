# Universal wallet

`GET /api/v1/me/wallet` accepts a personal Network bearer token and returns all three balances, their currency and purpose, available checkout offers, the latest five Billing/Network events with source sites, current-month AI usage and both the Billing freeze and Live’s owner money_writes_frozen switch. Available Balance is denominated in USD at nano-USD precision; there is no invented FX conversion. OpenCoins remains on Network's ledger: Billing forwards the verified person's bearer only to configured Network read endpoints, without cookies or redirects. Upstream errors are failures, never zero balances. First-party origins receive bearer CORS; hosting tenants do not.

`POST /api/v1/me/vibes/buy` takes `{provider,vibes,idempotency_key}`. `POST /api/v1/me/wallet/topups` takes `{provider,amount_cents,idempotency_key}`. Both fix the buyer to the token, compute prices/fees server-side, respect the freeze, and return the existing hosted checkout URL. The sheet navigates in the same tab. A durable claim is saved before contacting the provider; completed requests replay the original checkout and changed payloads fail. An uncertain provider result stays pending and requires confirmation before another payment is started. Existing provider webhooks settle the original intent.

`POST /api/v1/me/store/spend` takes only `{purchase_id}`. Billing obtains the immutable order from configured Inventory with the person's bearer. Vibes spending and its receipt commit atomically, with funds and freeze checks. OpenCoins debits go to Network with Billing's service token and a deterministic order key; an uncertain reply is recovered by replaying that key. Inventory grants only after matching the confirmed payment. Ledger writes stay in their current authoritative service; Inventory has no balance copy.

The owner switch is read from LIVE_URL (default https://openvibe.live) at /api/payments/wallet-state. If that read fails, balances remain readable and wallet writes pause.

Rollout prerequisites: `INVENTORY_URL` defaults to Inventory's public origin. Network must grant Billing `network.coins.debit` for audience `openvibe.network`, scoped to app `billing`, before OpenCoins purchases work. The existing owner settings must enable and configure checkout providers and top-ups. Consuming sites must allow `https://billing.openvibe.network` and `https://inventory.openvibe.network` in connect-src when pinning the Shared wallet release. Nothing here changes production grants, prices, settings or deployment.
